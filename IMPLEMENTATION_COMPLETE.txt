THE 10-LAYER PIPELINE:

  1. INPUT NORMALIZATION     ✓ mime-decoder + html-cleaner
     → Convert any email format to standard structure
  
  2. RECRUITMENT FILTER      ✓ recruitment-filter
     → Filter non-job emails (90% of inbox)
  
  3. DOCUMENT CLASSIFIER     ✨ NEW
     → Determine email type: confirmation|assessment|interview|offer|...
  
  4. EXTRACTION              ✓ parsers + field-extractors
     → Extract facts: company, role, salary, recruiter, date, links
  
  5. VALIDATION              ✓ validation
     → Check if facts make sense together
  
  6. FIELD RESOLUTION        ✨ NEW
     → Multiple extractors? Pick the most trustworthy value
  
  7. IDENTITY RESOLUTION     ✨ NEW
     → New application or update to existing? (hardest problem)
  
  8. STATE ENGINE            ✨ NEW
     → Track current state + history + valid transitions
  
  9. TIMELINE ENGINE         ✓ timeline-builder
     → Convert facts to readable timeline events
  
  10. OUTPUT BUILDER         ✓ sync-orchestrator (final)
      → Return perfect ParsedApplication

KEY INSIGHT: IDENTITY RESOLUTION (Layer 7)

The hardest problem: Does this email belong to a new application or existing?

WITHOUT Layer 7:
  Applied email → Row 1: "Applied to Google SWE"
  Interview email → Row 2: "Applied to Google SWE"
  Offer email → Row 3: "Applied to Google SWE"
  
  Dashboard shows 3 rows (confusing!)
  Database stores duplicates
  Merge logic needed everywhere

WITH Layer 7:
  Applied email → Parsing
  Interview email → Recognized as continuation of Row 1 (99% confidence via thread ID)
  Offer email → Recognized as continuation of Row 1 (95% confidence via recruiter)
  
  Database stores 1 row with state history:
    - Applied Aug 1
    - Interview Aug 5  
    - Offer Aug 10
  
  Dashboard shows 1 logical application with timeline

═══════════════════════════════════════════════════════════════════════════════

RESOLUTION SIGNALS (Layer 7) - PRIORITY ORDER:

  1. Same Gmail Thread ID
     Confidence: 99%
     Why: Definitive. Same email conversation.
  
  2. Same Recruiter + Company + Role
     Confidence: 95%
     Why: Very strong signal of continuation.
  
  3. Same Company + Role within 7 days
     Confidence: 92%
     Why: Likely same application (assessment → interview, etc)
  
  4. Same Company + Role within 30 days
     Confidence: 85%
     Why: Possible same application.
  
  5. Fuzzy Match 85%+ within 60 days
     Confidence: 75%
     Why: Probably same but needs review.

CORE PRINCIPLE:

A good architecture answers ONE question at each layer:

1. What is this email?                    (Normalization)
2. Should I care about it?               (Classification)
3. What TYPE of recruitment email?       (Document Understanding) ✨
4. What facts can I extract?             (Extraction)
5. Are those facts valid?                (Validation)
6. Which facts are most trustworthy?     (Resolution) ✨
7. Which application does this belong to?(Identity) ✨
8. What is the current state?            (State Engine) ✨
9. How should user see this history?     (Timeline)
10. What structured output?              (Builder)

Answer these 10 questions perfectly = 98% accuracy.
